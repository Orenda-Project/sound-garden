# Sound Garden: build plan

Citation key as in DESIGN.md (R1..R4 research files, C1..C4 critics). Course source: `/home/oye/Documents/free_work/sound-out` (set as `SOUND_OUT`). Everything below is a plan; no code exists yet.

## 1. Stack and reasons
| Choice | Why |
|---|---|
| **Vite + vanilla JS (ES modules), no UI framework** | sound-out's prototype is already Vite vanilla, so gate logic and content loaders port directly; a framework would cost 40+ KB gz before the first letter on a 2 GB Android (R4 §2 sizes: the runtime cost gap is two orders of magnitude). |
| **Inline SVG + CSS custom properties** for UI, garden and Sprig | Compositor-only transform/opacity animation is the cheapest path on weak CPUs (R4 §2, §5 pick C); palette tokens drop straight into `:root` (R2 §2). |
| **Mascot runtime: hand-rolled WAAPI state machine (`mascot.js`, about 2 KB)**, Motion mini (2.3 KB) only if needed | R4 decision 2. No Lottie player, no Rive, no WASM at first paint. GSAP stays out unless level-up proves fiddly (R4 §5). dotLottie only lazily for rare celebrations if the spike shows headroom (R4 decision 10). |
| **Sprig generated by Python (`make_sprig.py` from `sprig.yaml`)** | Profile-to-all-states idea from agent-face (R4 §3); our own MIT code, so python-lottie's AGPL is not involved (R4 §5, C4 fix 5 resolved: we do not use it). |
| **Hash router, single `index.html`, hand-written service worker** | Static hosting anywhere (GitHub Pages or Cloudflare Pages, free); no server, no cookies, no accounts (R1 §4.10; R3 §2.5 rejects Web Push because it needs a server). |
| **`localStorage` state, about 300 B JSON** | R3 §2.8: tiny state, single store, try/catch. |
| **Audio: Ogg Opus clips, lazy per lesson, `<audio>`/WebAudio decode on demand** | sound-out already ships 898 `.ogg` (6.2 MB for the levels built so far) keyed by `audio_index.json` clips. |
| **Tests:** Vitest for pure logic (gates, scheduler, garden code), Playwright for screenshots and the critic harness | Reuses the Playwright capture method behind R1. Commit capture scripts (C1 fix 2). |
Hosting is not decided here; GitHub Pages is the default because the repo is already on GitHub.

## 3. Content pipeline (sound-out JSON to the site)
Read: `content/lessons/L1.01..L1.14.json` (keys seen: id, level, title, goal, newToday, review, listen, check, appSittings; `appSittings` is null for some, e.g. L1.01, and `app/src/level1.js` `fillL1` supplies sittings), `content/levels/L2..L4.json` (lessons, lexicon, g2p, gateItems, audioKeys), `content/sessions/L5.01..` (warm, word, prime, write, check, text, fluency, discuss, screens), shared `lexicon.json` 52 KB, `options.json` 148 KB, `gpc.json` 20 KB, `audio_index.json` (clips keyed `w:`/`ph:`, 0.9 speed ElevenLabs River voice).
`tools/build_content.py` does, in order:
1. Load all of the above (sound-out stays the single source of truth; we never edit it).
2. Strip authoring fields (`source`, `blocksFound`, `contentVersion`, `heartLine` prose), keep what the engine reads.
3. Emit **one JSON per level** plus `shared.json` (lexicon, gpc, tap-gate options for items used), so a level loads lazily; gzip target in section 4.
4. Build the **gate pool per lesson (12+ items, no 2-option items)** from lesson items and `options.json` (R3 §2.7). **Known gap:** `L1.01.json` check is `pass 4 of 5`, below the 12-item gate in R3; M0 must verify each lesson check can supply 12 items, else build a pool from the lesson's words and mark `needsItems` in a report. Treat this as a likely blocker for L1.01 as written.
5. Map `audio_index.clips` to files; mark each key `real` or `placeholder` in `audio-map.json`. CI fails if a Level 1 key is `placeholder` (L1 audio must be real).
6. Emit `content-report.md`: lessons, items per gate, missing audio by level, bytes by level.
**Reuse, not UI:** port the pure logic of `app/src/gate.js` (2x2 option grid, repair after a first wrong: replay the printed word's sounds, no whole-word reveal) and read `app/src/scheduler.js` (not read yet; verify it matches R3 §2.2 intervals 20 h/3/7/14/30 d before reusing). Do **not** reuse `app/src/screens/*`, `ui.js`, `style.css`, `onboarding.js`, `home.js`.
**Audio status:** Level 1 real; L2-7 placeholders (voice route undecided). Placeholder behaviour: captions on, a short non-speech tone per sound, and the tap-gate for L2-7 cannot be completed by ear. So in M2 later levels are playable in a `?dev=1` mode, and the public build shows zones 2-7 as terrain with "Sounds being recorded". Dropping in real audio is a content rebuild with no code change.

## 4. Size and performance budget (gzip, to lock after the spike)
| Page / state | Budget | Basis |
|---|---|---|
| Shell: HTML + CSS tokens + core JS (router, store, mascot, sheet) | JS 45 KB, CSS 12 KB, font 30 KB | R4 §2 (runtime 2 KB vs 75-500 KB) |
| **S1/S2 first load** (inline Sprig seed stage, no audio) | **60 KB total**, no third-party requests | R1 §4.1 |
| Sprig | 15 KB per stage, 12 animated nodes max, `states.json` 10 KB | R4 §5 |
| **Lesson player** (adds gate/tiles logic + level JSON) | +30 KB JS, level JSON at most 80 KB, audio per lesson at most 400 KB lazy | measure; L1 share of the 6.2 MB is unmeasured |
| **Home/Garden** (zone renderer, symbols) | +40 KB JS/SVG; at most 400 live DOM nodes; 6 ambient animated elements | R3 risk 5, R4 §5 |
| Whole app JS | at most 150 KB gz | Motion: tune after spike |
| First session to sprout (L1.01) transferred | at most 600 KB incl. audio | NEW target; time-to-first-fun 90 s needs it |
`tools/size_budget.mjs` fails CI on any breach. Performance rules: transform/opacity only, pause on `visibilitychange`, one mascot animation at a time, still-pose fallback if frame time over 32 ms for 10 frames (R4 §5). Target: interactive under 3 s on throttled 3G-fast emulation and measured, not assumed, on the real phone.

## 6. Milestones
Every milestone ends with (1) a demo URL or build, (2) a **blind-comparison critic test**, (3) the playtest gate where marked. Critic protocol: `tools/critic_capture.py` screenshots our screen at 390x844 and 1280x800 in the matching state; two separate critic agents (cheap models per Kamal's rule) see our shot and the Duolingo/TYM shot **order-swapped, unlabelled**, and score clarity of next action, delight, calm of the text area, and hierarchy. **Win = both critics prefer ours or call it equal on at least 3 of 4 criteria, with no loss on clarity.** Loop until it wins (gauntlet-loop). Bar screens live in `research/shots/teardown/`.

## 7. Metrics (no accounts, R3 §2.5; C1 fix 5: each decision gets a number)
Instrument locally (30-bit tended-day bitmap, first-day, time-to-first-change). Pilot testers send their garden code. Targets are hypotheses to tune, not promises: time to first sound 10 s or under; time to watered seed 90 s or under; D1 return 35% (floor 22%); D7 15% (floor 8%); first bloom within 3 days 50% (floor 30%) (R3 §2.5). State that numbers from shared codes are biased toward engaged learners.

## 8. Risks carried into the build
1. The garden becomes the toll, not the learning (R3 risk 1): gates stay mastery-only; no time in the garden rewarded.
2. Silent data loss (R3 risk 2): code card at every landmark, home-screen install prompts.
3. Placeholder audio for L2-7 means the tap-gate cannot be judged by ear; do not publish those levels as playable until audio lands (see section 3).
4. Single-source dependency: sound-out content shape could change; pin `SOUND_OUT` to a commit and record it in `content-report.md`.
5. Unread: `app/src/scheduler.js`, `app/src/level1.js` internals and sound-out `plan/`; verify before porting.
6. Everything about child vs adult tone, Sprig's look, and colour in sun is unverified until Gate 1 and Gate 2 (R2 Decisions, R4 Gaps).
