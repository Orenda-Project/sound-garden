## 1. Stack and reasons
| Choice | Why |
|---|---|
| **Vite + vanilla JS (ES modules), no UI framework** | sound-out's prototype is already Vite vanilla, so gate logic and content loaders port directly; a framework would cost 40+ KB gz before the first letter on a 2 GB Android (R4 §2 sizes: the runtime cost gap is two orders of magnitude). |
| **Inline SVG + CSS custom properties** for UI, garden and Sprig | Compositor-only transform/opacity animation is the cheapest path on weak CPUs (R4 §2, §5 pick C); palette tokens drop straight into `:root` (R2 §2). |
| **Mascot runtime: hand-rolled WAAPI state machine (`mascot.js`, about 2 KB)**, Motion mini (2.3 KB) only if needed | R4 decision 2. No Lottie player, no Rive, no WASM at first paint. GSAP stays out unless level-up proves fiddly (R4 §5). dotLottie only lazily for rare celebrations if the spike shows headroom (R4 decision 10). |
| **Sprig generated by Python (`make_sprig.py` from `sprig.yaml`)** | Profile-to-all-states idea from agent-face (R4 §3); our own MIT code, so python-lottie's AGPL is not involved (R4 §5, C4 fix 5 resolved: we do not use it). |
| **Hash router, single `index.html`, hand-written service worker** | Static hosting anywhere (GitHub Pages or Cloudflare Pages, free); no server, no cookies, no accounts (R1 §4.10; R3 §2.5 rejects Web Push because it needs a server). |
| **`localStorage` state, about 300 B JSON** | R3 §2.8: tiny state, single store, try/catch. |
| **Audio: Ogg Opus clips, lazy per lesson, WebAudio; the seed tap unlocks the context** (LR b) | sound-out holds **2,898 `.ogg` files, 14.6 MB** counting copies (LR g, CB). The app-served set, `app/public/audio`, is 898 files, 6.2 MB; `app/dist` and `docs` hold duplicates. We copy only keys we use, deduplicated by clip id, and report the real total in `content-report.md`. |
| **CI: `.github/workflows/ci.yml`** on every push: `npm ci`, build, `node tools/size_budget.mjs`, `python3 tools/build_content.py --check`, Vitest | CB: "fails CI" had no CI. |
| **Tests:** Vitest for pure logic (gates, scheduler, garden code), Playwright for screenshots and the critic harness | Reuses the Playwright capture method behind R1. Commit capture scripts (C1 fix 2). |
Hosting is not decided here; GitHub Pages is the default because the repo is already on GitHub.

## 3. Content pipeline (sound-out JSON to the site)
Read: `content/lessons/L1.01..L1.14.json` (id, level, title, goal, listen, check, appSittings; `appSittings` is null, and `app/src/level1.js` `fillL1` supplies sittings), `content/levels/L2..L4.json` (lessons, lexicon, g2p, gateItems, audioKeys), `content/sessions/L5.01..` (warm, word, prime, write, check, text, fluency, discuss, screens), `lexicon.json` 52 KB, `options.json` 148 KB, `gpc.json` 20 KB, `audio_index.json` (clips keyed `w:`/`ph:`, ElevenLabs River, speed 0.9).
`tools/build_content.py`, in order:
1. Load the above (sound-out is never edited) and the pinned commit check.
2. Strip authoring fields (`source`, `blocksFound`, `contentVersion`), keep what the engine reads.
3. Emit **one JSON per level** plus `shared.json`, so a level loads lazily.
4. **Gate pool (LR e, CB fix 1).** The finding: L1.02-L1.13 checks have 11 items each (5 real, 5 pseudo, 1 dictation; bars 9/11 or 10/11); L1.01 has no item list (`freeResponse`, bar 4/5); L1.14 has no count. So **13 of 14 Level 1 gates are below the 12-item rule** (R3 §2.7), not only L1.01. We **add items, we do not lower the bar.** `content-overlay/L1.NN.json` lists extra items `{kind, word, options}` with at least 3 options (no 2-option items count). The builder merges them, counts only items with 3+ options, and **exits non-zero if any gate has fewer than 12.** Pass mark = 80% of 12 = 10 of 12 (R3 §2.2). **Overlay sizing and time-box:** about 14 lessons x 1 to 3 extra items, roughly 40 items. The generator is `sound-out/tools/gen_options.py` (Level 1 ladder; it writes `content/options.json` and `options_report.md` **in sound-out, which must stay untouched**): run it only inside a throwaway `git worktree` of sound-out at `3283e35` in the scratchpad, then copy the new entries into `content-overlay/`. Time-box **one working day**; if it overruns, fall back to words that already have an options entry and drop the rest of the lesson's extra items only if the gate still reaches 12. Overlay words are chosen first from lexicon words that already have an `options.json` entry and real audio, so no new recording is needed; if a lesson has no such word, run the sound-out option generator once into the overlay (`tools/` command recorded in `content-report.md`) and re-run the foil check.
5. **L1.01 oral pool of 12**, authored from the `oralCheck` sitting in `app/src/screens/l1oral.js` (which today judges 5 words, `CHECK = sat, top, pig, dog, mat`, bar 4/5): the 5 CHECK blend-and-pick items, 3 more blends from `BLEND` (at, it, on), and 4 first-sound picks from `FIRST` (sun, top, pig, dog), every item with 3+ spoken options. 12 oral items, all with existing audio keys (`ph:` and `w:`).
6. Map `audio_index.clips` to files; mark each key `real` or `placeholder` in `audio-map.json`; **CI fails if any Level 1 key is `placeholder`.**
7. Emit `content-report.md`: sound-out commit, **both bars per lesson: sound-out's own (9/11 or 10/11) and the overlay bar (10/12)**, items per gate (before and after overlay), missing audio per level, bytes per level, de-duplicated audio total.
**Reuse, not UI:** port the pure logic of `app/src/gate.js` (2x2 option grid; repair after a first wrong replays the printed word's sounds, no whole-word reveal). `app/src/scheduler.js` and `level1.js` internals are not read yet: verify intervals 20 h/3/7/14/30 d (R3 §2.2) before reusing. Do **not** reuse `app/src/screens/*`, `ui.js`, `style.css`, `onboarding.js`, `home.js`.
**Audio status:** Level 1 real; L2-7 placeholders (voice route undecided). Placeholders show captions with a short non-speech tone, and the spoken-option tap-gate cannot be judged by ear, so L2-7 are `?dev=1` only; the public build shows zones 2-7 as terrain with "Sounds being recorded". Real audio later is a content rebuild, not a code change.

**Pre-M0 checks (run before M0 day 1; scripts `tools/pre_m0_check.py`, results in `plan/pre-m0.md`; any failure blocks M0 until fixed or the item is dropped from the pool):**
- A. For every Level 1 gate item and every foil in `options.json` for Level 1 words, each option's audio key exists in `audio_index.json` `clips` **and** the file exists in `app/public/audio`.
- B. Every `oralCheck` item (CHECK, plus the BLEND and FIRST items taken into the 12-item pool) offers 3 or more spoken options **via the `blendWord` code path in `app/src/screens/l1oral.js`**: read what `blendWord` actually passes as the `pool`, and fail if any item gets fewer than 3 distinct spoken options.
- C. Pin check: `git -C $SOUND_OUT rev-parse --short HEAD` equals `3283e35`.

## 4. Size and performance budget (gzip; locked in `tools/size_budget.mjs`, enforced by CI)
**First load (HTML, CSS, JS, SVG, manifest, icons; every request until the seed tap): at most 90 KB gzipped, hard cap** (LR f; CB fix 2 showed 45+12+30 font+15 Sprig = 102 KB did not fit). Arithmetic: JS 45 + CSS 12 + Sprig stage 1 SVG 15 + HTML, manifest, icons 8 = **80 KB, 10 KB spare**. **No web font on first load**: system font stack until the first sprout (S6), then Andika (about 30 KB subset) lazy-loads and is cached. The first sitting's audio prefetches after load and is outside the 90 KB (see below).
| Page / state | Budget | Basis |
|---|---|---|
| Shell JS (router, store, mascot, feedback area) | 45 KB | R4 §2 (runtime 2 KB vs 75-500 KB) |
| Sprig | 15 KB per stage, at most 12 animated nodes, `states.json` 10 KB lazy | R4 §5 |
| Lesson player (lazy, after the seed tap) | +30 KB JS, level JSON at most 80 KB, **lesson audio at most 400 KB lazy**, sitting 1 prefetched at most 150 KB | measure; the real per-lesson audio size is unmeasured |
| Home/Garden (lazy) | +40 KB JS/SVG; at most 400 live DOM nodes; **at most 12 animated nodes counting Sprig** (9 planned, see DESIGN S3) | LR c; R4 §5 |
| Whole app JS | at most 150 KB gz | tune after spike |
| Seed tap to first sprout, total transferred | at most 600 KB including audio and Andika | NEW; the 90 s watering needs it |
`size_budget.mjs` fails on any breach; `.github/workflows/ci.yml` runs it on push. **"Slow network" means Chrome DevTools preset Fast 3G (1.6 Mbps down, 150 ms RTT) with 4x CPU throttle**, a smoke test; the real number comes from the phone. Rules: transform/opacity only, pause on `visibilitychange`, one mascot animation at a time, still-pose fallback if frame time is over 32 ms for 10 frames (R4 §5). Target: first sound within 10 s of the Start tap, seed watered within 90 s of it.

## 6. Milestones
Every milestone ends with (1) a demo URL or build, (2) a **blind-comparison critic test**, (3) the playtest gate where marked. Critic protocol: `tools/critic_capture.py` screenshots our screen at 390x844 and 1280x800 in the matching state; two separate critic agents (cheap models per Kamal's rule) see our shot and the named shot **order-swapped, unlabelled**. **M0 judges only (1) clarity of the next action and (2) the no-wall check**: a grey-box cannot win on delight or hierarchy, so those are not scored (CB, LR i). **M0 win rule (numeric): on each of the 5 named clarity pairs in the M0 row, both critics prefer ours or call it equal on clarity of next action (5 pairs x 2 critics = 10 of 10 verdicts are "ours" or "equal"; any single "theirs" sends that screen back for a fix and a re-run), AND the no-wall check passes (zero form fields, zero redirects, one tap from `/` to the first sound, verified by the drive script).** **From M1** the criteria are clarity, delight, calm of the text area and hierarchy; win = both critics prefer ours or call it equal on at least 3 of 4, with no loss on clarity. Loop until it wins (gauntlet-loop). Bar shots: `research/shots/teardown/`; the analysis behind them is R1, now written and revised, with scripts in `research/tools/teardown/`.

## 8. Risks carried into the build
1. The garden becomes the toll, not the learning (R3 risk 1): gates stay mastery-only; no time in the garden rewarded.
2. Silent data loss (R3 risk 2): code card at every landmark, home-screen install prompts.
3. Placeholder audio for L2-7 means the tap-gate cannot be judged by ear; do not publish those levels as playable until audio lands (see section 3).
4. Single-source dependency: sound-out content shape could change; pin `SOUND_OUT` to a commit and record it in `content-report.md`.
5. Unread: `app/src/scheduler.js`, `level1.js` internals and sound-out `plan/`; verify before porting.
6. R1 metric targets are the author's own with no baseline (its §4 preface); replace with measured values after week one.
7. Everything about child vs adult tone, Sprig's look, and colour in sun is unverified until Gate 1 and Gate 2 (R2 Decisions, R4 Gaps).
